# 分流配置

客户在已购服务中填写自己的 Shadowsocks、SOCKS5 或 WireGuard 出口，以及需要走该出口的域名/IP 规则。保存即启用；规则优先级、未命中时的处理和默认出口由现有 Remnawave Profile 决定。

## 自动识别已有服务

功能根据已购服务实际分配的服务器自动识别，复用该记录已有的私有 `settings.remnawave.api` 和 `token`。
无需添加套餐启用项、选择适配器或服务器，也无需新增安全配置。尚未分配服务器时不显示入口；原开通流程完成后，可重新打开服务详情查看。

分流在 SHM worker 内直接调用面板 API，不改变原服务器 transport 或账号生命周期事件。
部署沿用官方镜像、core 源码和前端构建文件挂载，不增加运行依赖、Compose 或 `.env` 参数。

模块只发布固定的 `Out Users`、`Routing Users` 两份 Snippet，确认目标名称唯一且内容为数组，只更新当前实例拥有的 `SHM_ROUTING_` 条目，保留其他条目。
模块不读取、展开、校验或改写 Profile。Snippet 引用、规则优先级和默认出口由 Remnawave 运维预设负责，不能仅凭个人规则的用户绑定推断全局默认行为不变。

## 固定校验

出口必须为公网地址，域名的全部 DNS 答案都要通过检查；面板 API 的解析地址禁止作为出口，发布时固定为已验证 IP。
这些检查无法识别所有 NAT、转发链或代理后方目标。访问面板时使用 HTTPS 与可信证书，沿用已有连接设置。

`geosite:`、`geoip:` 只校验语法，标签及数据文件由现有节点资源保证；此功能不维护白名单、不下载或核验节点资产。
该功能没有独立的 `remnawave.routing` 配置对象，提供该字段会返回 `INVALID_ROUTING_CONFIG`。

Snippet 名固定，单请求 30 秒、总计 90 秒，时区跟随现有 `TZ`，默认 `Asia/Shanghai`；均无需另行设置。

## 客户输入

客户界面保持两个输入框，示例放在灰色占位中：

- **出口**：支持常见 SS 分享链接、单出口 JSON、标准单 Peer WireGuard 配置，以及 SOCKS5 地址与认证格式。新保存的出口会一并加密保留原始文本；重新打开或刷新后，服务详情与连接信息并行预加载，按本人权限读取并按原格式回填，包括备注、注释和空白。留空沿用已保存凭据，未修改出口时仅保存规则，不重发凭据。原始输入按 UTF-8 字节最多 16KiB，完整机密对象序列化后最多 64KiB。
- **规则**：每行一个域名（含子域名）、`geosite:`、IP、CIDR 或 `geoip:`。拒绝 URL、正则、keyword、ext 和原始路由 JSON。

SOCKS5 可导入 `socks5://`、`socks://`、`socks5h://` 链接，`服务器:端口:用户名:密码`、`用户名:密码@服务器:端口`、`服务器:端口@用户名:密码`，以及竖线、逗号或空白分隔的四列、带标签的多行文本。IPv6 地址使用方括号；两侧都可解释为服务器时不猜方向，请改用显式 `socks5://` 链接。文本凭据按字面处理，仅 URI 的用户名和密码执行一次百分号解码。

也可导入只包含一个代理声明的 curl 示例，支持 `--proxy` / `-x`、`--socks5`、`--socks5-hostname` 和 `--proxy-user` / `-U`，以及一个末尾检测网址。只解析出口，检测网址不加入分流规则，不执行命令。SOCKS5 导入不改写平台的 DNS 或路由设置。

WireGuard 配置的 `[Interface] DNS` 由客户端转为出站 `settings.remoteDNS`；原生 WireGuard JSON 也可提供该字段。它只接受 1–8 个纯 IPv4/IPv6 地址，保留顺序和重复项，规范化地址写法，不接受主机名、搜索域、URL、端口、CIDR 或 zone。提供商的隧道内私网 DNS 可以使用，不受外层 peer 必须为公网地址的限制。未填写时不注入应用默认值，由 Xray 使用该出站的原生默认行为。

`remoteDNS` 仅用于解析送到 WireGuard 出站时仍为域名的被代理目标，查询通过该用户的 WireGuard 隧道发送，不更改平台全局 DNS 或其他用户。客户端已解析为 IP，或平台在交给此出站前已将目标解析为 IP 时，不会再由它重新解析。peer 的 `Endpoint` 仍由 SHM 检查全部 DNS 答案并固定为已验证公网 IP，不使用隧道内 `remoteDNS`。DNS 地址必须能经该 peer 的 `AllowedIPs` 到达，导入不会自动扩展路由。节点使用的 Xray 需要支持 `remoteDNS`，本功能不会替管理员升级节点。[Xray 原生说明](https://xtls.github.io/config/outbounds/wireguard.html#outboundconfigurationobject)

查看使用专用的本人机密读取接口，响应禁止缓存；普通读取、保存响应及管理员接口仍只返回脱敏内容。原始文本放在机密对象的 `outbound_text`，与规范化 `outbound` 共用数据库 `options.secret` 加密保存，不放入公开 `data`，不另增明文字段或浏览器持久存储。公开 `data.outbound` 只保存协议、服务器和端口摘要，可省略；完整规范化出口仍在机密对象内，发布仅编译该对象，原文和公开摘要不进入远端 Snippet。切换详情页签复用当前读取，关闭详情或切换服务会取消过期请求。读取结果不会覆盖已经编辑的草稿；已移除的服务不能读取，未保存机密时保持空白。

“分流配置”页保留“出口”和“规则”两个输入框。说明为“每行一条规则，未命中的流量按现有平台路由处理。”底部只保留一个操作按钮，按当前操作显示保存并应用、启用分流或停用分流，不再另设状态圆点。按钮沿用客户界面的浅色、整行样式和默认圆角，按动作固定配色：保存为蓝色、启用为绿色、停用为橙色。执行期间保留当前动作颜色，显示加载动画并防止重复点击；操作失败仍保留动作配色，通过现有错误提示说明原因。按钮不可操作时沿用原生灰色禁用样式。同步状态及处理结果通过现有悬浮提示和错误提示显示，不改变按钮的动作配色。按钮文字、执行提示和错误信息提供全部八种内置语言的翻译。保存与连接读取设有局部超时；保存超时保留草稿，提示结果尚未确认，并重读一次脱敏状态，不自动再次提交。同步已提交仍不表示节点已经生效。

服务端重新校验，不能依赖前端预览。出站只接收受限协议字段，tag 和路由身份由模块生成。SS 2022 AES 支持合法 PSK 链，ChaCha20-2022 仅接受单 PSK；SOCKS5 最多一组认证；WireGuard 一个 Peer、1–8 个 Interface 地址、最多 64 个 AllowedIPs，固定 userspace，不执行配置中的脚本或改变平台全局 DNS。

规则通过 `us_<购买实例编号>` 查到的真实面板数值用户 ID 绑定，域名和 IP 分组为 OR 规则；空组不会变成无条件匹配。模块不改变用户统计身份、不重置流量、不修改套餐或到期时间。

## 管理员操作

管理端不另设分流配置区域。需要代用户查看或修改出口、规则、启停分流时，使用管理端原有的“进入用户中心”入口，在该用户的已购服务详情中操作，沿用用户中心的保存和权限检查。

需要重新应用当前配置时，先停用，等待停用任务成功完成且分流状态为 `disabled`，再启用。停用保留源凭据、原始出口文本和规则，无需重新填写。处理中不要快速连点切换启停；后台任务会重新读取当前意图，连续点击不能保证严格的先撤后建。

停用实际生效到再次启用实际生效之间，相关流量按平台既有路由处理。任务完成和 `submitted` 均不能证明节点已即时生效，需结合面板与节点实际状态确认。失败时先查看管理端现有任务队列中的 `SERVICE_OPTIONS` 任务及错误码，对仍在队列中的失败任务使用原有重试功能；已归档记录在任务历史中排查，需要修改输入时返回用户中心保存。

## 同步、停用与恢复

有效 ACTIVE 服务异步发布；服务暂停、到期或面板账号尚未建立时等待恢复。按钮执行停用动作时只提交停用意图，当前无效草稿不会阻止停用；远端条目删除后保留源凭据、原始出口文本与规则，供再次启用。

两份 Snippet 的更新与 sync 不是跨对象事务。模块在共享锁内保留最小加密恢复记录，重新核对未完成实例的当前状态，修复后再同步。当前停用或 REMOVE 优先于旧启用意图；半次启用遇到 BLOCK 时恢复发布前基线。无效草稿保留上一有效内容，不覆盖其它用户。

恢复时仍检查出口公网地址、全部 DNS 答案和面板 API 地址。来源或授权不可用时返回 `PENDING_SOURCE_UNAVAILABLE`；积累达到上限时返回 `PENDING_LIMIT`，保留原记录，先重试原失败任务再提交新实例。不要删除状态或替换密钥绕过错误。

普通读取的 `data[0].status` 是标量，失败时同层 `error` 为错误码；`submitted` 只表示面板受理并排队同步，不能据此断言节点已生效。超时后重试可能再次同步，共享节点可能重新加载。上线前用隔离账号检查真实出口握手、规则命中与未命中、停用、删除及实际节点状态。

到期保留配置；原 REMOVE 流程明确确认清理成功后才擦除源机密。保留窗口沿用原服务清理设置，不另设定时器。密钥和恢复文件位于现有共享 `/app/data/service-options`，与数据库一并备份。

## 失败排查

已知固定错误码会随安全提示显示在用户中心和现有任务记录中。任务的 `errors` 映射（如有）按购买实例编号列出失败码，混合批次应逐项排查。

- `SERVICE_OPTIONS_TARGET_CHANGED`：已保存的能力或目标与当前分配不符；先完成原目标停用，再应用新目标。`SERVICE_OPTIONS_TARGET_INVALID` / `SERVICE_OPTIONS_CONFIG_INVALID` 表示目标或持久结构无效，不能通过清空记录或替换密钥绕过。
- `REMOTE_IO` / `REMOTE_HTTP` / `REMOTE_RESPONSE`：从执行任务的 **spool 容器**检查面板 API 的网络、DNS、证书、Token 权限和接口兼容性。原账号生命周期的 SSH 成功不能证明这条连接正常。

按错误码处理原因后重试当前同步；需要修改出口或规则时在用户中心保存对应内容。不要删除密钥或恢复记录来清除错误，也不要直接修改 JSON 中的 `status` 为 `queued`：修改状态字段不会创建同步任务。

通用 API、权限和模块接口见[服务选项开发契约](service-options.md)。
